## v1.12.34 Alt+Fで分類候補を一覧

- Links検索中のコンパクトな分類表示はそのまま維持し、`Alt + F`を押したときだけ検索結果に含まれる分類候補を一覧展開します。
- 分類候補は `すべて` を先頭に、該当件数の多い順で表示します。各チップに件数も表示します。
- 候補は横方向に並べ、幅に収まらない場合は2段まで折り返します。3段目以降が必要な場合だけ、一覧枠の中を縦スクロールできます。
- `Alt + F → ← / →`で候補を移動し、`Enter`で分類を確定して一覧を閉じ、その分類で絞り込んだ先頭リンクへ移動します。
- マウスではコンパクトな分類ボタンを押して候補を開き、分類チップをクリックして選択できます。
- 検索語を変更しても選択中の分類が残っていれば維持し、0件になった場合だけ `すべて` へ戻します。
- POP／サイドパネルの両方を同じ操作と見た目に揃えています。

## v1.12.30 「？」と読みもののデザインを洗練

- サイドパネルの「？」を文字ではなく専用SVGアイコンへ変更し、28pxの丸ボタン内で光学的に中央へ揃えました。
- ボタンは普段は静かに見せ、hover／focus時だけ輪郭と明度が少し上がる設計にしています。
- 「このアプリについて」は通常の白いモーダルから切り離し、上質な本文紙をイメージしたごく薄い生成りの紙面へ変更しました。
- CSSの微細な粒子・繊維方向・濃淡だけで紙の質感をつくり、画像ファイルや強い古紙表現は使っていません。
- 本文だけ明朝系のOS標準フォントを使い、本文幅を約33em、行間を約2.08、段落間を約1.62emにして、情報密度を下げています。
- 文章を約1,050字へ再編集し、説明の連続を減らして「情景 → 道具の役割 → 余白 → 日常へ戻る」という一篇の流れに整理しました。
- 中央の一文だけを静かな間として扱い、カードや多数の小見出しで文章を分断しない構成にしました。
- 「操作説明」は紙面化せず、従来どおり実用性を優先したクリーンなUIとして明確に分離しています。

### 読ませるために使ったデザイン／文章テクニック

1. **UIと読みものを別の素材として扱う**：操作説明はアプリUI、紹介文は紙面という視覚言語に分け、読むモードへの切り替えを明確にする。
2. **紙を装飾ではなく低コントラストで再現する**：生成り色、極小の粒子、ほぼ見えない繊維方向だけを重ね、古紙やノート風にはしない。
3. **一行を短くする**：本文幅を絞り、サイドパネルの横幅いっぱいに文字を流さない。視線が次の行を見つけやすくなる。
4. **行間より段落間をさらに大きく取る**：文章の意味のまとまりごとに呼吸をつくり、「壁」のように見える長文を避ける。
5. **一文だけの段落を“間”にする**：強調ボックスを置く代わりに、中央配置と余白だけで読み手の速度を少し落とす。
6. **機能を列挙しない**：「何ができるか」より「どんな瞬間に手が止まり、どう次へ進むか」を描き、機能はその風景の中へ溶かす。
7. **最後に売り込まない**：CTAではなく、道具が日常へ馴染んだ未来の風景で終え、読後の余白を残す。


## v1.12.29 LINE WORKS channelIdの重複判定を強化

- 右下POPでLINE WORKSのchannelIdを数字／UUIDだけで入力したとき、同じIDが登録済みなら入力中に「このLINE WORKS IDは登録済みです」と表示します。
- `line.worksmobile.com/message/send?...&channelId=...` と `talk.worksmobile.com/join?...&channelId=...` のようにURL形式が違っても、channelIdが同じなら同一リンクとして判定します。
- `version`やクエリパラメータ順が違う場合も、channelIdが同じなら重複として扱います。
- LINE WORKSのトーク系URL内で、ハッシュ内の`channelId`や明示的な`/message/<ID>`等の形式も重複判定に利用します。
- 保存時にも同じ判定を行うため、入力中の表示だけでなく実際の二重登録も防ぎます。
- 既存データに同じリンクのactive／archivedが両方残っている場合はactiveを優先し、誤ってアーカイブ側を復元して二重化しないようにしました。
- 同じ共通判定をサイドパネルと右クリック追加にも利用します。



## v1.12.28 サイドパネルの「このアプリについて」／操作説明

- サイドパネルのタイトル横へ小さな「？」ボタンを追加しました。右下POPには表示しません。
- 「？」を押すと、最初に「このアプリについて」を直接開きます。
- 説明文は機能一覧ではなく、日々の「どこだっけ」で作業が止まる瞬間から始まる約3分の短いコラムとして構成しました。
- 説明文の末尾から「操作説明」へ進め、操作説明から説明文へ戻れます。
- 操作説明は「開く・探す・追加する・REDS検索・右下POP」に分け、主要ショートカットとマウス操作をまとめています。

### 説明文の文体設計

説明文は、小さな小説・コラムを読んだような余韻をつくるため、次の方針で書いています。

1. 機能説明より先に、仕事中に手が止まる具体的な一場面を置く。
2. 「検索機能がある」ではなく「思い出せる言葉を少し打てば戻れる」のように、人の行動として機能を書く。
3. 長めの段落の途中に短い一文を置き、文章に呼吸をつくる。
4. アプリを強く擬人化せず、「右下にいる」「近くにいる」程度の距離感にとどめる。
5. 操作仕様は本文へ詰め込まず、別の「操作説明」に分離する。
6. 冒頭の「あれ、どこだっけ」を、末尾では「考える前に指が開く」という未来の風景へ変えて回収する。
7. 宣伝文句で締めず、使い続けた先の日常を想像できる一文で終える。

## 初期ルール

従来の自動分類を初期ルールへ移行しています。

例：

- `docs.google.com/spreadsheets` → スプレッドシート
- `drive.google.com` → ストレージ
- `github.com` → ツール
- `www.urawa-reds.co.jp` → クラブ発信
- `notion` → Notion

既に自動分類ルールを保存している場合、アップデート時に上書きしません。

## 使い方

1. サイドパネルを開く
2. 上部の「URL自動分類」にある「管理」を押す
3. 判定文字列と振り分け先を入力して「追加」を押す
4. 必要に応じて、ルール左側の `≡` をドラッグして順番を変更する
5. 下部の「判定テスト」で動作を確認する

ルールは変更のたびに自動保存されます。

## 判定例

次の順番で登録した場合：

1. `docs.google.com/spreadsheets` → スプレッドシート
2. `docs.google.com` → Googleドキュメント

スプレッドシートのURLは両方に一致しますが、上にある「スプレッドシート」が採用されます。

## 手動分類との関係

- URL入力時、分類をまだ手動変更していなければ自動判定が反映されます。
- 分類を手動変更すると、その入力中は手動設定を優先します。
- 「再判定」を押すと、現在のURLをルールでもう一度判定します。

## 分類名を変更・削除した場合

- 分類名を変更・統合すると、関連する自動分類ルールの振り分け先も更新します。
- 分類を削除すると、その分類を参照していたルールは削除せず無効化します。

1. ZIPを展開する

## ショートカット

- `Alt + 1`：Linksを開く
- `Alt + 2`：REDSを開く
- `Alt + 3`：Promptを開く
- `Alt + 5`：右下POPを完全に非表示
- `Alt + 4`：共通の検索語をクリア／検索語が空なら現在の検索欄へ移動
- `Alt + N`：新規追加を開く
- `Alt + F`：Links検索中だけ分類候補を1〜2段で一覧表示（`← / →`で選択、`Enter`で先頭リンクへ）
- `Alt + Q`：Linksを開き、表示中の一番上のリンクを選択（`↑↓`でリンク移動、`→`でコピー、コピーから`↓`で編集、`←`でリンクへ戻る）
- `Alt + S`：REDSのサイト検索を実行
- `Alt + X`：浦和レッズ公式Xを検索
- `Alt + W`：右下POPを小さくする

Chromeのショートカット設定に表示されるのは`Alt + 1`、`Alt + 2`、`Alt + 3`、`Alt + 4`です。`Alt + 5`、`Alt + N`、`Alt + Q`、`Alt + S`、`Alt + X`、`Alt + O`、`Alt + F`、`Alt + W`は拡張機能内で直接処理するため、`chrome://extensions/shortcuts`には表示されません。
